# 天地图候选数据核验（2026-10-30）

用户从天地图行政区划页面下载并提供中国*省.geojson、中国*市.geojson、中国\_县.geojson。本次直接读取下载目录原件，没有修改原件、提交原始数据或切换客户端的数据源。核验结果支持将其作为优先替换候选，不能据此认定离线再分发授权已经解决。

## 来源与文件身份

- 官方入口：https://cloudcenter.tianditu.gov.cn/administrativeDivision
- 当前页面说明：数据更新时间“2026 年 10 月”，更新内容“局部数据更新”，“本数据仅供地图可视化使用”。这些是页面说明，下载文件没有版本、日期、许可或审图号字段，不能认定各地区统一更新于该月。
- 三份 GeoJSON 的 crs 均声明 urn:ogc:def:crs:EPSG::4490，即 CGCS2000。此为文件声明，本次没有用控制点验证坐标基准。
- 属性只有 name、gb，没有显式父级、区划基准日或行政级别字段。gb 是带 156 前缀的九位字符串，应作为来源标识保留，不能无条件解释为现行行政区代码。

## 检查结果

使用 Python 3.12、Shapely 2.1.2 检查全部要素：无空几何、无解析错误、无非有限坐标，无超出经纬度有效范围的包络，所有几何通过 is_valid。各层面要素 gb 无重复。没有执行 buffer(0)、make_valid、简化、坐标量化或修复。

按 gb 前缀归组，并优先处理跨文件相同代码的整体占位项，得到 409 组对比。其中 47 组是同代码整体代理，例如省级和市级文件中的北京市，或市级与县级文件中的省直管县；不能把这些对比解释为真实的完整下级分区验证。其余 362 组比较父面与下级面合并的范围。没有未归组或多重归组的子面。

集合运算使用原始经纬度平面，计算对称差／并集面积，仅作一致性筛查，不代表实际土地面积。409 组中没有超过 1% 的差异，最大为锦州市约 0.035784%；葫芦岛市约 0.017922%。同组子面之间没有发现超过 1e-8 比例的面积重叠。组间层级来自编码推断，尚未与权威父子名录逐项比对。

## 覆盖差别

- 台湾在市级文件中是整体，在县级文件中有 20 个市县面，包括台北、新北、高雄、澎湖等。没有这些市县以下的区、乡镇明细，不能等同当前旧库的台湾区县覆盖。
- 金门县编码 156350527，在该数据中按福建侧编码归组；不能按旧库父级强行归入台湾。各来源区划组织方式不同，应明确保留来源事实。
- 香港县级文件有 18 区。
- 澳门县级文件仅澳门整体，没有原有堂区等明细。
- 375 和 2,890 是相应下载文件的面记录数，包含特殊层级代理，不能宣称为全国地级／县级行政单位总数。
- 文件中有境界线，但仅凭 name 无法区分每条线的性质。本次未对海陆边境线逐段人工验图，也不能确认已覆盖全部标准制图表达。
- 三份文件没有独立国家外轮廓。全国省份分区可由省级面组成，国家纯轮廓及各层级纯轮廓应设计统一的生成和验收流程，避免继续使用互不一致的旧 shape_only 数据。

## 接入建议

优先采用天地图作为新的统一主数据源，保持原始精度及 CGCS2000 声明；将边界面、境界线和导航目录分开处理。原始文件应固定校验值，记录下载入口及页面说明。离线随包分发前需进一步核对授权，GitHub 的 MIT 不能授权这套独立来源数据。

接入时需要显式处理直辖市、港澳、台湾、省直管县，建立来源 ID 与应用 ID 的映射，并迁移旧偏好。台湾下级区和澳门明细若保留旧来源，应作为具有单独来源及坐标说明的补充，不能冒充天地图覆盖或直接无缝拼接。

本次完成的是候选文件核验，没有进行客户端替换。原文件已由用户保存在本机，只有审计脚本与说明提交到仓库。

## 重复核验

需要 Python 3.10+、Shapely 2.x。从仓库根目录运行：

    python desktop/scripts/audit-tianditu.py "C:/Users/ligx/Downloads/data" --output desktop/artifacts/tianditu-verification.json

脚本以只读方式检查输入，输出逐文件哈希、覆盖、几何问题、编码归组及全部父子范围比较。无效几何或集合运算失败会报错，不自动修复。结构问题、缺失／多重父级、范围差异超过 1%、重叠超过 0.1% 时返回失败。此阈值只用于异常筛查，不能作为行政边界准确性证明。Shapely 为维护核验依赖，不是客户端运行依赖。
